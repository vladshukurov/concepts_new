# Образы — архитектура

Клиентское приложение без своего бэкенда: аккаунты, лента и сообщения живут на SDK провайдера, медиа — в его же хранилище. Ни один заявленный ключ не требует писать и разворачивать свой обработчик.

Набор доступов — ВКонтакте, заявлен 21 ключ из 22: `BGTaskSchedulerPermittedIdentifiers` не заявлен — у отдельной фоновой задачи нет фичи, до которой человек дошёл бы за 2–3 тапа. Фоновое обновление ленты видно в самой ленте («Новые образы к утру»), а не тумблером в настройках. Правило, из которого выведена вся таблица ниже: **доступ заявляется только там, где за ним стоит фича, до которой пользователь доходит за 2–3 тапа.**

## Модель домена

<!-- @generated:domain-model -->
| Сущность | Что это | Состояния | Экраны |
|---|---|---|---|
| Автор | человек с профилем — тип пользователя в продукте один | не подписаны → подписаны | `profile`, `post`, `nearby`, `mates` |
| Образ | публикация: фото и отмеченные вещи | черновик → опубликован | `home`, `post`, `create`, `profile` |
| Клип | видео-примерка с субтитрами | черновик → с субтитрами → опубликован | `clip`, `subtitles` |
| Своп | встреча обмена: место, часы, участники, сеть площадки | скоро → идёт → завершён | `swap`, `checkin`, `netqr`, `nearby` |
| Вещь на свопе | то, что человек приносит; ведущая проверяет её до приёма | заявлена → на проверке → принята → отклонена | `swap`, `chat`, `call` |
| Диалог | переписка с автором или чат свопа | есть непрочитанные → прочитан | `chats`, `chat`, `call` |
| Разбор | аудиовыпуск о гардеробе | не начат → на паузе → дослушан | `talk`, `background` |

## Информационная архитектура

## Действия на экранах

Каждый интерактивный элемент прототипа: что он делает, куда ведёт и какой ключ при этом запрашивается. В отличие от таблицы переходов выше, вкладки таб-бара, кнопки возврата и подтверждения без перехода тоже здесь — раздел выводится из разметки и отвечает на вопрос «что делает эта кнопка», не заставляя открывать HTML.
