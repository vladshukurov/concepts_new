# Вешалка — архитектура

Клиентское приложение без своего бэкенда: аккаунты и сообщения живут на SDK провайдера, медиа — в его же хранилище. Ни один заявленный ключ не требует писать и разворачивать свой обработчик.

Набор доступов — ВКонтакте, заявлен 21 ключ; `BGTaskSchedulerPermittedIdentifiers` держит ночную сборку плана образа на завтра. Фоновое обновление ленты видно в самой ленте («Новые образы к утру»), а не тумблером в настройках. Правило, из которого выведена вся таблица ниже: **доступ заявляется только там, где за ним стоит фича, до которой пользователь доходит за 2–3 тапа.**

## Модель домена

<!-- @generated:domain-model -->
| Сущность | Что это | Состояния | Экраны |
|---|---|---|---|
| Человек | знакомый или ведущая свопа — тип пользователя в продукте один | знакомы → на свопе | `profile`, `post`, `nearby`, `mates` |
| Образ | свой образ: фото, вещи, погода и повод | черновик → в лукбуке → в плане | `home`, `post`, `create`, `profile` |
| Клип | видео-примерка с субтитрами | черновик → с субтитрами → в лукбуке | `clip`, `subtitles` |
| Своп | встреча обмена: место, часы, участники, сеть площадки | скоро → идёт → завершён | `swap`, `checkin`, `netqr`, `nearby` |
| Вещь на свопе | то, что человек приносит; ведущая проверяет её до приёма | заявлена → на проверке → принята → отклонена | `swap`, `chat`, `call` |
| Диалог | переписка с ведущей свопа или знакомым | есть непрочитанные → прочитан | `chats`, `chat`, `call` |
| Разбор | своя голосовая запись о гардеробе | записывается → на паузе → дослушан | `talk`, `background` |

## Обоснование доступов

Кто, когда и почему без доступа фича не работает — из `permissions[].rationale`.

<!-- @generated:access-rationale -->
| Ключ | Кто | Когда | Почему без доступа не работает | Что остаётся после отказа |
|---|---|---|---|---|
| `camera` | Человек, который ведёт свой лукбук | Утром у зеркала нажимает «Снять» в новом образе | Образ в полный рост снимается сейчас, в том, что надето; из галереи такого кадра нет | Образ из фото медиатеки или без кадра — только вещи |
| `photos` | Человек, у которого удачные образы уже в галерее | В новом образе нажимает «Из медиатеки» | Старые снимки образов лежат в медиатеке — без доступа их не перенести в лукбук | Новый образ снимается камерой в приложении |
| `mic` | Человек, который перебирает шкаф | На «Разборе голосом» нажимает «Записать разбор» | Руки заняты вещами — разбор записывается только голосом с микрофона | Список вещей набирается вручную |
| `location` | Человек, который ищет своп или ателье рядом | На вкладке «Рядом» нажимает «Показать рядом со мной» | Расстояние до свопов и мастерских считается только от текущего места | Свопы и мастерские по выбранному району |
| `push` | Человек, который собирается утром | В настройках включает «План образа утром» | План на день приходит в 8:00 сам, пока приложение закрыто | План виден в лукбуке при открытии |
| `remotenotif` | Человек с вещью на свопе | Без жеста: ведущая меняет статус вещи | Тихий пуш обновляет статус вещи в лукбуке и на свопе до открытия | Статус обновляется при открытии |
| `fetch` | Человек, который открывает лукбук утром | Без жеста, к первому открытию | План на завтра по прогнозу собирается в фоне из своих вещей, к утру он уже в лукбуке | План собирается в момент открытия |
| `bgtask` | Человек, который открывает лукбук утром | Ночью, пока телефон заряжается, без жеста | Без зарегистрированного идентификатора iOS не запустит ночную сборку плана образа | План собирается в момент открытия |
| `appgroups` | Человек с виджетом плана на экране «Домой» | Добавляет виджет из настроек | Виджет читает план образа только через общую группу приложения | План виден только внутри приложения |
| `keychain` | Человек, который открывает лукбук из виджета | Нажимает на виджет на экране «Домой» | Сессия хранится в общей связке ключей — иначе из виджета открывается вход | Повторный вход по номеру и паролю |
| `autofill` | Человек, который заказывает вещи на сайте марки | Открывает кабинет магазина в Safari со входом из «Вешалки» | Почта и пароль магазина подставляются в Safari без копирования | Пароль вводится вручную |
| `wifiinfo` | Человек, пришедший на своп | Нажимает «Отметиться на свопе» | Отметку подтверждает сеть площадки, а не слово участника | Отметка по коду со стойки |
| `contacts` | Человек, который ищет знакомых для свопа | В профиле нажимает «Найти среди контактов» | Кто из знакомых ходит на свопы, видно только сверкой своей книги на устройстве | Знакомые находятся по имени |
| `tracking` | Человек, которому показывают рекламу винтажа и ателье | Выбирает подбор на экране «Реклама» | Без разрешения реклама магазинов не учитывает район | Реклама без подбора, лукбук бесплатный так же |
| `faceid` | Человек, у которого в лукбуке сохранённые образы и черновики | Включает «Замок Face ID» в настройках | Сохранённое и черновики не должны открываться с чужих рук | Замок по код-паролю устройства |
| `speech` | Человек, снявший клип-примерку | Нажимает «Субтитры к клипу» | Текст к своему клипу распознаётся на устройстве, без ручного набора | Субтитры вписываются вручную |
| `audio` | Человек, который записал разбор шкафа | На «Разборе голосом» нажимает «Слушать» | Своя запись играет с погашенным экраном и управляется с локскрина | Запись играет, пока открыт экран |
| `calendar` | Человек, идущий на своп | На вкладке «Свопы» нажимает «Добавить в Календарь» | Полный доступ нужен, чтобы перенести уже добавленный своп, если ведущая сдвинет время | Своп и напоминание остаются в приложении |
| `hotspot` | Человек у стойки свопа с QR-кодом | Сканирует QR и нажимает «Подключиться» | Подключить телефон к Wi‑Fi площадки из приложения можно только через HotspotConfiguration | Имя сети и пароль показаны текстом |
| `commnotif` | Человек с вещью на проверке | На свопе нажимает «Сообщить, когда примут» | Уведомление показывает имя и аватар ведущей — видно, кто принял вещь | Обычное уведомление без имени |
| `voip` | Человек в чате с ведущей свопа | Нажимает «Позвонить» в шапке диалога | Входящий видеозвонок ведущей приходит на заблокированный экран только через VoIP-пуш и CallKit | Фото вещи и голосовые в чате |

## Действия на экранах

Каждый интерактивный элемент прототипа: что он делает, куда ведёт и какой ключ при этом запрашивается. В отличие от таблицы переходов выше, вкладки таб-бара, кнопки возврата и подтверждения без перехода тоже здесь — раздел выводится из разметки и отвечает на вопрос «что делает эта кнопка», не заставляя открывать HTML.
