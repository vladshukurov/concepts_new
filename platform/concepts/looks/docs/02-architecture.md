# Вешалка — архитектура

Клиентское приложение без своего бэкенда: аккаунты и сообщения живут на SDK провайдера, медиа — в его же хранилище. Ни один заявленный ключ не требует писать и разворачивать свой обработчик.

Набор доступов — ВКонтакте, заявлен 21 ключ; у трёх фоновых ключей три разных следа: план на завтра «собран в 6:40» в лукбуке (fetch), «Пересчитано в 3:12» — что висит без дела, в профиле (bgtask, `app.vesh.wear`), «Принят Лерой в 9:33» — статус своей вещи на свопе (remotenotif). Ни одного тумблера доступа в настройках нет. Правило, из которого выведена вся таблица ниже: **доступ заявляется только там, где за ним стоит фича, до которой пользователь доходит за 2–3 тапа.**

## Модель домена

<!-- @generated:domain-model -->
| Сущность | Что это | Состояния | Экраны |
|---|---|---|---|
| Человек | знакомый или ведущая свопа — тип пользователя в продукте один | знакомы → приглашён → на свопе | `profile`, `mates`, `chats`, `swap` |
| Образ | свой образ: фото, вещи, погода и повод | черновик → в лукбуке → в плане | `home`, `post`, `create`, `profile` |
| Клип | видео-примерка с субтитрами | черновик → с субтитрами → в лукбуке | `clip`, `subtitles` |
| Своп | встреча обмена: место, часы, участники, сеть площадки, очередь на приём | впереди → в Календаре → идёт → завершён | `swap`, `checkin`, `netqr`, `fill` |
| Вещь на свопе | то, что человек приносит; ведущая проверяет её до приёма | дома → на проверке → принята → отклонена | `swap`, `chat`, `call`, `background` |
| Диалог | переписка с ведущей свопа, общим чатом свопа или знакомым | есть непрочитанные → прочитан | `chats`, `chat`, `chat-group`, `chat-yura`, `chat-mark`, `call` |
| Разбор | своя голосовая запись о гардеробе | записывается → на паузе → дослушан | `talk`, `background` |

## Обоснование доступов

Кто, когда и почему без доступа фича не работает — из `permissions[].rationale`.

<!-- @generated:access-rationale -->
| Ключ | Кто | Когда | Почему без доступа не работает | Что остаётся после отказа |
|---|---|---|---|---|
| `camera` | Человек, который ведёт свой лукбук | Утром у зеркала нажимает «Снять» в новом образе | Образ в полный рост снимается сейчас, в том, что надето; кадр сразу встаёт в форму образа | Образ из снимков медиатеки или только вещи без кадра |
| `photos` | Человек, у которого удачные образы уже лежат в галерее среди тысяч снимков | В новом образе нажимает «Найти образы в медиатеке» | Приложение само находит снимки в полный рост у зеркала по всей медиатеке — пикер умеет только выбрать то, что человек уже нашёл сам | Новый образ снимается камерой |
| `mic` | Человек, который снимает себя в двух вариантах одной вещи | В камере нажимает «Снять примерку» | Видео со звуком без микрофона не пишется, а субтитры к клипу распознаются из этого звука | Фото у зеркала без клипа |
| `location` | Человек, который снимает образ дня | В новом образе нажимает «Погода здесь» | Образ ценен погодой, в которую он сработал: она берётся по месту, где человек сейчас, а не по городу из профиля | Район для погоды выбирается вручную |
| `push` | Человек, который отметил «Надену» на плане завтрашнего образа | На карточке плана нажимает «Напомнить в 8:00» | Утром, пока приложение закрыто, план с прогнозом приходит сам | План виден в лукбуке при открытии |
| `remotenotif` | Человек, который отдал вещи на своп | Без жеста: ведущая принимает вещь, приложение закрыто | Тихий пуш обновляет статус вещи на устройстве, и при открытии он уже верный | Статус обновляется после открытия, с задержкой |
| `fetch` | Человек, который открывает лукбук утром | Без жеста, к первому открытию | План на завтра по прогнозу собирается в фоне из своих вещей, к утру он уже в лукбуке | План собирается в момент открытия |
| `bgtask` | Человек, который собирает вещи на своп | Ночью, пока телефон заряжается, без жеста | Распознать вещи на сотнях снимков образов — долгая работа; iOS запускает её только по зарегистрированному идентификатору на зарядке | Список пересчитывается при открытии профиля, дольше и с разряженной батареей |
| `appgroups` | Человек, который хочет видеть план на завтра, не открывая приложение | На карточке плана нажимает «На экран «Домой»» | Виджет читает план образа только через общую группу приложения | План виден только внутри приложения |
| `keychain` | Человек, которому пишут по свопу, пока экран заблокирован | Юра отвечает в чате свопа | Текст сообщения хранится зашифрованным; расширение уведомлений достаёт ключ из общей связки и показывает превью | В уведомлении только «Новое сообщение», текст виден после входа в приложение |
| `autofill` | Человек, который несёт вещи на своп | На свопе открывает «Анкету вещей на сайте свопа» в Safari | Организаторы принимают анкету только на своём сайте; аккаунт туда завела «Вешалка» при записи на своп, и вход подставляется из неё без копирования | Почта и пароль вводятся вручную |
| `wifiinfo` | Человек, пришедший на своп с вещами | Во дворе площадки нажимает «Отметиться на свопе» | Место в очереди на приём даёт только присутствие: имя сети сверяется с сетью площадки, а не со словом участника | Отметка по коду со стойки у ведущей |
| `contacts` | Человек, который идёт на своп и хочет взять подругу | На свопе нажимает «Позвать на своп» | Кто из знакомых уже в «Вешалке», а кого пригласить ссылкой, видно только сверкой своей книги на устройстве | Поиск по имени и ссылка-приглашение |
| `tracking` | Человек, который видит одну рекламную карточку в лукбуке | На экране «Реклама» выбирает «По интересам» | Без разрешения реклама не подбирается по интересам | Реклама без подбора, лукбук так же бесплатный |
| `faceid` | Человек, у которого в «Сохранённом» мерки и размеры | В профиле открывает «Сохранённое» | Мерки — личное: с чужих рук раздел не должен открываться | Замок по код-паролю устройства |
| `speech` | Человек, снявший клип-примерку | На клипе нажимает «Субтитры» | Текст к своему клипу распознаётся на устройстве из его звука, без ручного набора | Пустые строки по меткам времени для ручного ввода |
| `audio` | Человек, который записал разбор шкафа | Едет на своп и на «Разборе голосом» нажимает «Слушать» | Своя запись играет с погашенным экраном и управляется с локскрина, а названные вещи отмечаются «оставить» или «на своп» | Запись играет, пока открыт экран |
| `calendar` | Человек, который собирается на барахолку в воскресенье | В разделе «Дальше» на свопах нажимает «В Календарь» у барахолки | Полный доступ нужен, чтобы поправить уже добавленную встречу, если организатор сдвинет время | Встреча остаётся в приложении |
| `hotspot` | Человек у стойки свопа с QR-кодом | Сканирует QR и нажимает «Подключиться» | Подключить телефон к Wi‑Fi площадки из приложения можно только через HotspotConfiguration | Имя сети и пароль показаны текстом |
| `commnotif` | Человек, у которого жакет на проверке у ведущей | На свопе нажимает «Сообщить, когда примут» и гасит экран | На локскрине сообщение приходит от Леры с её именем и фото, тап открывает диалог | Обычное уведомление «Вешалки» без имени |
| `voip` | Человек, у которого жакет на проверке | На свопе нажимает «Показать жакет ведущей» | Ведущая смотрит подкладку и ярлык вживую; звонок идёт через CallKit и не обрывается при блокировке | Фото вещи и голосовые в чате |

## Переходы

## Действия на экранах

Каждый интерактивный элемент прототипа: что он делает, куда ведёт и какой ключ при этом запрашивается. В отличие от таблицы переходов выше, вкладки таб-бара, кнопки возврата и подтверждения без перехода тоже здесь — раздел выводится из разметки и отвечает на вопрос «что делает эта кнопка», не заставляя открывать HTML.
