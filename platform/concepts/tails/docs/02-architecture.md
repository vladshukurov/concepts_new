# Выгул — архитектура

Клиентское приложение без своего бэкенда: аккаунты, дневник, прогулки и сообщения живут на SDK провайдера, медиа — в его же хранилище. Ни один заявленный ключ не требует писать и разворачивать свой обработчик.

Набор доступов — ВКонтакте, заявлено 20 ключей. Правило, из которого выведена вся таблица ниже: **доступ заявляется только там, где за ним стоит фича, до которой пользователь доходит за 2–3 тапа.** Причина живёт в review-notes, фича — в сборке, а проверяют фичу.

## Обоснование доступов

Кто, когда и почему без доступа фича не работает — из `permissions[].rationale`.

<!-- @generated:access-rationale -->
| Ключ | Кто | Когда | Почему без доступа не работает | Что остаётся после отказа |
|---|---|---|---|---|
| `camera` | Владелец на прогулке | В новой записи нажимает «Снять» | Момент снимается сейчас, на площадке; в галерее его нет | Запись с фото из медиатеки или без фото |
| `photos` | Владелец, у которого фото уже в галерее | В новой записи нажимает «Из Фото» | Снимки питомца лежат в медиатеке — без доступа их не перенести в дневник | Фото снимается камерой в приложении |
| `mic` | Владелец, который заметил странное | В наблюдении нажимает «Надиктовать наблюдение» | Наблюдение пишется голосом — руки заняты поводком | Наблюдение набирается текстом |
| `location` | Владелец, который ищет компанию | В дневнике нажимает «Показать рядом» | Прогулки и площадки рядом считаются только от текущего места | Прогулки по выбранному району |
| `push` | Владелец, записанный на прогулку | На прогулке нажимает «Сообщить о переносе» | Перенос или новое место сбора приходят, пока приложение закрыто, — иначе можно прийти к пустому пруду | Перенос видно при открытии |
| `remotenotif` | Владелец, записанный на прогулку | Без жеста: кто-то присоединился или отказался | Тихий пуш обновляет состав прогулки до открытия приложения | Состав обновится при открытии |
| `fetch` | Владелец, который открывает дневник утром | Без жеста, к первому открытию | Прогулки на сегодня подтягиваются в фоне | Обновление в момент открытия |
| `bgtask` | Владелец перед поездкой на дачу | В «Без сети» нажимает «Скачать к утру» | Ветпаспорт и дежурный врач скачиваются ночью — днём их не успеть | Без сети ветпаспорт недоступен |
| `appgroups` | Владелец с прогулкой вечером | Ставит виджет из настроек | Виджет читает прогулку только через общую группу приложения | Прогулка видна только в приложении |
| `keychain` | Владелец, которому пишет клиника | Клиника переносит приём, телефон заблокирован | Сообщения клиники шифруются — расширение уведомлений берёт ключ из общей связки с приложением, иначе на экране блокировки только «Новое сообщение» | Превью без текста, сообщение видно в приложении |
| `autofill` | Владелец, который записывается к врачу | Открывает кабинет клиники в Safari со входом из «Выгула» | Телефон и пароль клиники подставляются в Safari без копирования | Пароль вводится вручную |
| `wifiinfo` | Владелец, который ставит автокормушку дома | Дома, на экране кормушки нажимает «Взять домашнюю сеть» | Кормушке нужно имя домашней сети — приложение берёт его с телефона, а не просит набрать «Kseniya-5G» с ошибкой | Имя сети вводится вручную |
| `contacts` | Владелец, который ищет друзей по прогулкам | В профиле нажимает «Найти среди контактов» | Кто из знакомых уже гуляет, видно только сверкой книги на устройстве | Друзья находятся по ссылке |
| `tracking` | Владелец в бесплатной версии | Из карточки рекламы в дневнике открывает «Реклама» и нажимает «Подбирать по интересам» | Без разрешения сеть не знает, какой у него питомец, — карточка остаётся общей | Реклама без подбора |
| `faceid` | Владелец, у которого в приложении номер чипа и наблюдения | В настройках включает «Замок Face ID» | По номеру чипа питомца находят в базе с адресом владельца — номер и наблюдения скрываются и открываются только после Face ID | Номер чипа под код-паролем устройства |
| `speech` | Владелец с голосовым наблюдением | В карточке питомца нажимает «Надиктовать заметку» | Голос превращается в строки наблюдения на устройстве | Наблюдение остаётся голосом |
| `calendar` | Владелец перед приёмом | У ближайшего приёма нажимает «В Календарь» | Приём и прививки записываются в календарь рядом с другими делами | Сроки остаются в приложении |
| `hotspot` | Владелец, который ставит автокормушку дома | Нажимает «Подключиться к кормушке» | У кормушки своя сеть для настройки — приложение подключается к ней само, передаёт домашнюю сеть и порции и возвращает телефон домой | Подключиться к сети кормушки в Настройках Wi‑Fi и вернуться в приложение |
| `commnotif` | Владелец, который отметился на прогулку | Нажал «Я иду» и убрал телефон — Влада отвечает | Сообщение видно по имени отправителя на экране блокировки, и «Фокус» пропускает тех, с кем гуляете | Уведомление без отправителя, текст тот же |
| `voip` | Владелец, который задерживается | Нажимает «Позвонить» в шапке диалога | Звонок приходит на заблокированный экран только через VoIP-пуш и CallKit | Переписка и голосовые в чате |

## Модель домена

<!-- @generated:domain-model -->
| Сущность | Что это | Состояния | Экраны |
|---|---|---|---|
| Питомец | животное с ветпаспортом; фото — его, а не экрана | в профиле → на прогулке → на приёме | `pet`, `profile`, `home` |
| Прогулка | встреча на площадке: время, место, участники | собирается → идёт → прошла | `nearby`, `walk`, `places` |
| Приём | визит или видеоосмотр у ветеринара | назначен → перенесён → прошёл | `vaccine`, `chat` |
| Наблюдение | заметка владельца о самочувствии, голосом или текстом | записано → показано врачу | `vetnote`, `pet` |
| Запись | своя прогулка, фото или заметка о Трюфеле | черновик → в дневнике | `home`, `create` |
| Кормушка | автокормушка дома: сеть для настройки и расписание порций | не настроена → в домашней сети | `feeder`, `pet` |
| Диалог | переписка с владельцами и клиникой | есть непрочитанные → прочитан | `chats`, `chat`, `call` |
<!-- @end -->

## Информационная архитектура
